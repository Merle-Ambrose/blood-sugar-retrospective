## Angular 21 Conventions

This codebase uses Angular 21 functional APIs exclusively. Never use class decorators for these:

| Old decorator | Angular 21 functional |
|---|---|
| `@Input()` | `input()` / `input.required()` |
| `@Output()` | `output()` |
| `@ViewChild()` | `viewChild()` / `viewChild.required()` |
| `@ViewChildren()` | `viewChildren()` |
| `@ContentChild()` | `contentChild()` |
| `@HostListener()` | `host: { '(event)': 'handler()' }` in component metadata |
| `constructor(private svc: Svc)` | `private svc = inject(Svc)` |

All components use `ChangeDetectionStrategy.OnPush`. Use `@for`, `@if`, `@switch` control flow — never `*ngFor`, `*ngIf`, `*ngSwitch`. Use `afterNextRender()` for DOM-dependent setup (not `ngAfterViewInit`) — required for zoneless compatibility.

## Architecture Overview

This is a **fully client-side Angular app** — no backend. All CSV parsing, statistics, and pattern detection happen in the browser.

### State Management

`GlucoseDataService` (`src/app/services/glucose-data.service.ts`) is the single source of truth, implemented with Angular signals. It owns:
- `session` — the parsed `GlucoseSession` loaded from CSV
- `displayUnit` — `'mg/dL'` or `'mmol/L'` toggle
- `dateRange` — active filter window
- Derived `computed()` signals: `filteredReadings`, `displayReadings`, `statistics`, `patterns`

Components inject `GlucoseDataService` via `inject()` and read signals directly. The only `input()` props are on pure presentational leaf components (e.g., `ChartBandsComponent`, `RecommendationCardComponent`).

The app is **zoneless** — `provideZonelessChangeDetection` is used in `app.config.ts`.

### Data Flow

```
CSV file → CsvParserService.parseFile()
         → GlucoseDataService.loadSession()
         → filteredReadings (computed) → StatisticsService → statistics (computed)
                                       → PatternDetectionService → patterns (computed)
                                       → SvgChartService → SVG primitives → GlucoseChartComponent
```

### CSV Format (FreeStyle Libre)

The export is a **standard comma-delimited CSV** with this structure:

```
Row 0:  Glucose Data,Generated on,<date>,Generated by,<name>   ← metadata, skip
Row 1:  Device,Serial Number,Device Timestamp,Record Type,Historic Glucose mg/dL   ← headers
Row 2+: Libre app,<uuid>,09-22-2025 10:30 PM,0,225   ← data
```

Key parsing details:
- **Row 0** is metadata — skip it. **Row 1** is always the header row.
- **Timestamp format**: `MM-DD-YYYY HH:MM AM/PM` (12-hour, US format). Parse with explicit AM/PM handling.
- **Unit detection**: read from the column header name — `Historic Glucose mg/dL` vs `Historic Glucose mmol/L`. Do not guess from values.
- **Record Type 0** = historic glucose (keep). All other record types (e.g., 6 = device events) have an empty glucose column — skip them.
- Strip BOM (`﻿`) from the file start before splitting lines.
- All readings are stored internally in mg/dL. mmol/L values are converted on parse (× 18.018).

### SVG Charts

All charts are **built from scratch with SVG — no chart libraries**. `SvgChartService` handles all coordinate math:
- Fixed Y-axis range: 40–400 mg/dL (never auto-scaled, keeps band positions stable across sessions)
- Y mapping: `innerBottom − ((value − 40) / 360) × innerHeight` (SVG y increases downward)
- Gap splitting: consecutive readings > 30 min apart become separate `<polyline>` segments — no connecting line across sensor gaps
- Bands (low/target/high) are `<rect>` elements rendered behind the line layer

`GlucoseChartComponent` uses `ResizeObserver` on its host element (via `afterNextRender()`) to keep a `chartWidth` signal updated, which drives a `computed()` viewport used by all SVG coordinate calculations.

Use `[attr.points]`, `[attr.viewBox]`, `[attr.x]` etc. for SVG attribute bindings. Use `@for` in SVG templates.

### SASS

`src/styles/` holds shared partials: `_variables.scss`, `_mixins.scss`, `_reset.scss`, `_typography.scss`, `_animations.scss`. Each component's `.scss` imports what it needs via `@use '../../styles/variables' as *` — never imported globally.

Dark theme. Key tokens: `$color-background: #0f1117`, `$color-surface: #1a1d27`, `$color-line: #7986cb`, `$color-low: #ef5350`, `$color-target: #66bb6a`, `$color-high: #ffa726`.

### Internal Value Convention

Glucose values are **always stored and calculated in mg/dL** internally. `displayReadings` is the only signal that converts values for display. `SvgChartService` always receives mg/dL; axis labels are converted when `displayUnit === 'mmol/L'`.
